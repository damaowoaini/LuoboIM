# 群权限事务基础候选验证

本候选只验证独立的事务、群 revision、精确写入范围和持久缓存失效机制，尚未接入
14 个业务 RPC、8 个权限写入口、辅助申请写入口或运行服务。不能据本任务通过
宣称并发越权已修复。业务角色与入群身份修复仍由原专项和集成任务验收。

源码固定为 v2 的 12 个 Go 文件，使用项目原有 go.mod/go.sum 与协议模块清单，
不升级依赖。`inputs.json` 锁定全部正文、原基础设施和测试清单。原模型、RPC、
控制器不为本候选改动；新包只复制进 GitHub 临时目录进行验证。

两个独立任务共用相同测试正文、断言和 Mongo fixture，只有测试 adapter 不同：

- before：以测试专用 adapter 表达旧的“事务外查权限，再写目标成员”形状。
  必须精确复现一个撤权断言失败，并通过管理员、群主两个合法正控。这不是执行旧 RPC。
- after：运行全部 21 个顶层、预期 31 个子测试，要求零跳过、零失败，另执行 vet。
  包括真实 Mongo revision 冲突、跨群回滚、精确 scope、缓存义务及恢复，
  以及固定驱动的 Mock 事务重试、提交未知结果和预算检查。

已经实际通过：before精确预期断言失败并保留合法正控；after21顶层/31子测试全部
race通过、0skip、vet0。双ZIP原始事件和52成员已独立核验，Mongo/Redis残留0、
容器清理成功。首轮编译失败0测试、r1夹具失败原件保留；r2更正了测试实际工作

这仍只验收基础机制，不代表产品入口接入或运行部署。

“提交 ACK 丢失”回归是在真实已确认提交后，用私有测试 session 边界替换返回值，
用于检查不重跑业务；不声称制造了真实网络丢包。事务内部最多 20 秒，未知提交只重试
同一提交；缓存批次受上下文和数量限制。完整服务的 Redis 超时及启动/退出接线仍待做。

Fixture 复用已固定的 Mongo 副本集及 Redis 临时基础设施，仅监听 loopback。
每个测试只删除自己随机 claim 的临时数据库。无全局 flush、生产连接或用户数据。
始终保存原始输出、统计数据库残留，并精确清理本次拥有的两个容器；清理失败使任务失败。
本任务复用 fixture，不冒充原先必跑 54 项集成测试已再次执行。

通过后仍须完成全部入口和低层写入保护、回调身份封存、托管缓存恢复生命周期，
再通过真实 RPC 并发及完整群服务回归，才能采用或部署。
